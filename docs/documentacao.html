Sistema de Login Seguro

1 Introdução

Este trabalho apresenta um sistema simples de cadastro e autenticação de usuários. A aplicação foi organizada para que a interface possa ser adaptada a diferentes temas sem alterar as regras principais de segurança.

2 Objetivo

O objetivo é demonstrar cadastro, login, logout e autorização por perfil usando Java, Spring Boot, Spring Security, Thymeleaf e MongoDB. O sistema define os perfis ADMIN, PROFESSOR e ALUNO.

3 Estrutura do sistema

O projeto separa responsabilidades em pacotes. Os controladores recebem as requisições; os serviços executam tarefas de cadastro e localização de usuários; o repositório acessa o MongoDB; e os modelos representam os dados. As páginas HTML Thymeleaf ficam separadas dos arquivos CSS.

O cadastro público cria somente usuários ALUNO. Essa decisão evita que uma pessoa obtenha privilégios administrativos escolhendo um perfil no formulário. O primeiro administrador pode ser criado por variáveis de ambiente, sem gravar uma senha no código-fonte.

Na página administrativa, o perfil ADMIN pode consultar a lista de usuários, alterar seus perfis ou excluir contas. O sistema impede a alteração ou exclusão da conta usada pelo próprio administrador e protege a última conta com perfil ADMIN. Ao alterar um perfil ou excluir uma conta, as sessões correspondentes são encerradas.

4 Integração com MongoDB Atlas

A aplicação recebe a URI do banco pela variável de ambiente MONGODB_URI. Assim, a credencial não precisa ser incluída no repositório. No Atlas, é necessário criar um usuário de banco, permitir o IP de conexão e usar a URI fornecida pelo serviço.

Os usuários são guardados na coleção usuarios. As sessões HTTP são guardadas no MongoDB pela integração Spring Session, na coleção sessoes. Para desenvolvimento sem Atlas, a configuração padrão usa um servidor MongoDB local.

5 Segurança e decisões de design

O Spring Security gerencia a autenticação e restringe as rotas pelo perfil. As senhas são codificadas com BCrypt antes de serem armazenadas. A validação verifica nome, formato de e-mail e tamanho da senha. A proteção CSRF do Spring Security permanece ativa nos formulários.

As telas usam Thymeleaf e recebem o nome do tema pela configuração APP_TEMA. Um novo arquivo CSS pode personalizar a apresentação sem modificar os controladores ou as regras de autorização. Em ambiente real, o sistema deve ser publicado com HTTPS e credenciais próprias.

6 Execução e adaptação

Com JDK 17, Maven e MongoDB disponíveis, defina MONGODB_URI e execute mvn spring-boot:run. A aplicação fica disponível na porta 8080. O arquivo README descreve a configuração local e a estrutura do código.

Para adaptar o projeto a um tema de PFC, é possível alterar textos, páginas e folhas de estilo. As regras de usuário, autenticação e autorização podem continuar separadas e ser reaproveitadas.
