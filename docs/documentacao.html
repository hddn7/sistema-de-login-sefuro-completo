Sistema de Login Seguro

1 Introdução

Este documento apresenta um sistema de login feito para uma atividade de estudo. Nele, uma pessoa pode criar uma conta, entrar e sair do sistema. Cada usuário vê as páginas permitidas para o seu perfil.

2 Objetivo

A aplicação usa Java, Spring Boot, Spring Security, Thymeleaf e MongoDB. Ela tem três perfis: ADMIN, PROFESSOR e ALUNO. As páginas e os estilos ficam separados das regras de acesso. Assim, a aparência pode ser alterada sem refazer o login.

3 Estrutura do sistema

O código Java está separado em pastas. Os controladores recebem as ações das páginas. Os serviços cuidam do cadastro e da busca de usuários. O repositório conversa com o banco, e o modelo guarda os dados de cada conta. As páginas HTML ficam na pasta de templates e o CSS fica separado.

O cadastro cria contas com o perfil ALUNO. Só o administrador pode mudar um perfil ou excluir outra conta. Ele não pode excluir a própria conta nem remover o último administrador. Quando um perfil muda ou uma conta é excluída, as sessões daquela pessoa são encerradas.

O primeiro administrador pode ser criado com as variáveis ADMIN_EMAIL e ADMIN_PASSWORD. Esses valores não ficam escritos no código-fonte.

4 Integração com MongoDB Atlas

A conexão é configurada na variável MONGODB_URI. No Atlas, é preciso criar um usuário do banco, permitir o endereço IP usado e copiar a URI de conexão. A URI deve ficar em uma variável de ambiente, não no GitHub.

Os dados das contas ficam na coleção usuarios. As sessões ficam na coleção sessoes. Para testar sem Atlas, a configuração também aceita um MongoDB instalado no computador.

5 Segurança e decisões de design

O Spring Security controla o login e protege as páginas de cada perfil. Antes de salvar uma senha, o sistema usa BCrypt para transformá-la em um hash. O formulário também confere o nome, o e-mail e o tamanho da senha. A proteção CSRF continua ativa.

As páginas usam Thymeleaf. A variável APP_TEMA escolhe o arquivo CSS. Para mudar as cores e a aparência, pode-se criar outro arquivo de estilo sem alterar as regras do login. Em um sistema publicado, deve-se usar HTTPS e uma senha forte para o banco.

6 Execução e adaptação

Para executar, instale o JDK 17, o Maven e tenha acesso ao MongoDB. Configure MONGODB_URI e rode mvn spring-boot:run no terminal, dentro da pasta do projeto. Depois, abra http://localhost:8080 no navegador.

Para usar o projeto em outro tema, podem ser trocados os textos das páginas e os arquivos CSS. O cadastro, o login e o controle dos perfis ficam separados dessas mudanças.
